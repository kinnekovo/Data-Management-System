# 第一阶段最终报告

## 完成内容

项目已从 M1 基础环境扩展为第一阶段完整业务系统。创建者可注册登录、创建草稿、管理题目和规则、发布/关闭问卷并查看统计；填写者登录后按动态路径逐题作答。后端对身份、所有权、题型、路径、截止时间和重复策略进行强制校验，MongoDB 保存业务数据并实时聚合统计。

## 关键成果

- 四种底层题型：单选、多选、文本、数字；
- 可视化配置条件跳转，规则只允许向后，后端重放路径防伪造；
- 匿名仅对创建者隐藏身份，仍保留登录和重复策略；
- MongoDB 唯一索引处理禁止重复提交的并发竞争；
- 选项计数、数字均值/极值、文本和原始答卷分页；
- Windows 一键脚本、本地 MongoDB、独立测试/演示数据库护栏；
- 统一错误模型、加载/空/错误状态和响应式 Vue 页面。

## 系统与 MongoDB 设计

Vue 通过 Vite `/api` 代理访问 FastAPI；FastAPI lifespan 管理同步 PyMongo 客户端与幂等索引。`users` 保存账号和 Argon2 哈希，`surveys` 内嵌一起读取的题目/选项/规则定义，`responses` 独立增长并引用问卷和填写者。问卷定义不会随答卷数量膨胀，统计直接从 responses 聚合产生。五个业务索引分别保证用户名、slug、列表排序、答卷分页和并发重复提交约束。

## 跳转、校验和隐私

规则按优先级首个命中，只允许向后跳。前端逐题计算路径，返回修改时清理旧分支答案；服务端从第一题重放路径并重新检查题型、必答和边界，因此客户端不能伪造被跳过题答案。匿名问卷依然要求登录，API 对创建者隐藏身份，数据库保留 respondent ID 以执行重复策略。

## AI 使用过程

Codex 先读取设计、课程需求和 M1 工程，再按账号、问卷、规则/提交、统计、前端、测试和文档顺序实现。依赖安装、MongoDB 集成、浏览器两账号闭环和 PowerShell 脚本均实际执行。AI 生成内容由自动化测试和浏览器操作校验；没有声称人工修改，也没有自动提交 Git。完整过程和错误记录见 `docs/ai-usage-log.md`。

## 实现问题与修复

浏览器测试曾发现：进入分支后的多选题时，路径清理删除了预设空数组，Vue 将复选框退化为布尔模型，勾选一项会让全部选项同步。实现改为显式维护选项 ID 数组，并重新完成浏览器闭环验证。部署脚本也补充检查 JWT 和密码库依赖，避免旧虚拟环境仅含 M1 依赖时误判为完整。
