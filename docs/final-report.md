# 项目完成报告

## 1. 项目目标

完成一个基于 MongoDB 的可运行问卷系统，使创建者能够设计、发布和统计问卷，使填写者能够按条件路径完成作答。系统需要体现文档数据库建模、索引、聚合、权限控制、输入校验和可复现测试。

## 2. 系统设计

系统采用 Vue 3 + Vite 前端、FastAPI 后端和 MongoDB 数据库。前端通过 `/api` 代理访问后端；后端按 `api / core / db / repositories / schemas / services` 分层。JWT 和 Argon2 负责认证，统一错误模型负责前后端反馈，PowerShell 脚本负责 Windows 本地检查和启动。

已完成账号、问卷/题目管理、四类题型、发布/关闭、条件跳转、填写、匿名展示、重复策略、实时统计和分页查看答卷。

## 3. MongoDB 设计

`users` 保存账号和密码哈希；`surveys` 嵌入题目、选项和规则，以一次查询读取完整定义；`responses` 独立增长并引用问卷和填写者。`backend/app/db/schema.py` 集中定义三个集合的 `$jsonSchema` 与五个索引。唯一用户名、唯一 slug、列表排序、答卷分页和并发防重均有对应索引。

这种设计兼顾了问卷定义的聚合读取和答卷的独立扩展，避免把不断增长的提交记录嵌入问卷。

## 4. 跳转设计

规则按 `priority` 升序取首个命中项，仅允许跳向后续题目，从结构上避免循环。前端即时计算路径并在前置答案变化时清理旧分支答案；后端从第一题重新执行路径，不接受客户端自报的访问顺序。路径外、未知或重复题目答案都会被拒绝。

## 5. 校验设计

系统采用三层校验：Pydantic 约束请求形状和规模，服务层检查题型/规则/路径语义，MongoDB Schema 约束最终存储字段。发布时校验完整问卷；提交时检查必答、选项、数组去重、文本长度、有限数字、整数/范围、状态、截止时间和重复策略。禁止重复提交由唯一部分索引处理并发竞争。

## 6. AI 使用过程

Codex 用于读取课程需求和既有设计、生成前后端初稿、补充自动化测试、执行命令与浏览器回归、定位多选规则问题，以及本次代码和文档整理。所有生成结果均以源代码、pytest、Vite 构建和实际页面行为复核；没有把未执行项目写成通过。

主要过程：

1. 建立 FastAPI、Vue、MongoDB 和本地启动基础设施；
2. 实现认证、问卷、跳转、提交和统计闭环；
3. 添加单元测试、真实 MongoDB 集成测试和手工验收记录；
4. 根据测试结果修复多选跳转编辑器；
5. 按提交清单合并重复文档，并将 MongoDB Schema 提升为代码中的单一事实来源。

## 7. 测试结果

历史验收已完成健康检查、一键启动、演示数据、浏览器双账号闭环和响应式布局检查。六项课程核心 API 用例定向运行结果为 `6 passed`。本次结构调整后，全量后端测试为 `49 passed`，MongoDB Schema/索引 smoke 检查通过，Vite 8.3.4 生产构建成功；详细输入与输出记录见 [测试用例与结果](test-cases.md)。

未执行项：Docker 容器完整启动和 MongoDB 进程重启持久化验证；它们不是默认本地运行路径，文档不将其标记为通过。

## 8. 遇到的问题

- 中文路径下不同 Python 环境创建虚拟环境存在兼容差异；
- Docker Hub/守护进程受网络或权限限制，无法作为稳定默认验收入口；
- 多选跳转编辑器曾因空选项 ID 和复选框模型退化而无法保存自由组合；
- 仅有 Pydantic 模型和索引，缺少独立可提交的 MongoDB 集合 Schema；
- 测试、部署、AI 过程分散在多份 Markdown，内容重复且互相引用。

## 9. 如何解决

- 默认采用 Windows 原生启动脚本，并允许直接调用虚拟环境 Python；
- Docker 降为可选部署，`ready` 真实检查 MongoDB，脚本不伪造服务就绪；
- 前端为新增选项立即生成稳定 ID，并显式维护多选规则的 ID 数组；
- 新增 `app/db/schema.py`，启动时幂等创建/更新集合验证器并建立索引；
- 将提交材料收敛为 README、系统说明、数据库设计、API 说明、关键逻辑、测试用例和完成报告七份必要 Markdown。

## 10. 当前边界与后续方向

当前问卷发布后冻结。若继续开发，应使用 `definition_version` 和不可变快照支持发布后编辑；大数据量场景可增加统计缓存或物化汇总。团队协作、文件题、导出和复杂图表仍属于后续范围。
